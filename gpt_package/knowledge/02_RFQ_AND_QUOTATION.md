# RFQ() 询价判断

## 1. 基本信息

```text
Skill ID: zayn-rfq
Display Name: RFQ()
Chinese Name: 询价判断
Project: WorkFn
Author Prefix: zayn
Category: RFQ and Quotation

Status: Draft for testing
```

## 2. 解决的问题

RFQ() 用于分析一条已经进入手中的询价，判断其真实程度、信息完整度、投入价值和下一步处理方式。它不负责阿里 RFQ 市场筛选，也不负责平台报价表填写。

## 3. 适用场景

适用于需要执行上述职责，且用户能提供相关询价、产品、价格或供应信息的场景。

## 4. 不适用场景

不适用于超出本 Skill 职责边界的市场批量筛选、平台表单提交、最终兼容性确认或其他专用任务。

## 5. 输入参数

输入分为必填参数和建议参数，必须先解析并形成参数状态表。

## 6. 必填参数

1. 客户或来源
2. 询价原文
3. 产品型号
4. 数量
5. 当前已知事实
6. 本次判断目标

## 7. 可选参数

1. 成色
2. 目标价
3. 交期
4. 项目背景
5. 历史合作
6. 付款方式
7. 保修
8. 替代接受度
9. 供应证据
10. 目的地
11. 客户明确时间节点

## 8. 证据优先级

1. 历史成交
2. 订单
3. 付款
4. 发货
5. 售后
6. 询价
7. 报价
8. 有效沟通
9. 公开资料
10. AI 推测

## 9. 判断规则

1. 已具备哪些成交信号
2. 缺失哪些关键信息
3. 需求是否真实
4. 是否值得投入找货和工程资源
5. 应快速响应、轻量报价、继续追问还是暂停
6. 报价必须写清哪些边界

## 10. 风险检查

1. 把普通询价直接判断为真实项目
2. 因型号明确就忽略数量、成色和交期
3. 把平台行为当成交信号
4. 为了响应速度跳过风险
5. 把未知信息补成事实
6. 与 ALI_RFQ_SCAN() 和 ALI_RFQ_BID() 混用

## 11. 输出结构

1. 参数完整度结论
2. 参数状态表
3. 已有成交信号
4. 缺失关键信息
5. 投入建议
6. 风险
7. 推荐下一步
8. 报价边界
9. 需要调用的下游 Skill

## 12. 禁止事项

1. 把普通询价直接判断为真实项目
2. 因型号明确就忽略数量、成色和交期
3. 把平台行为当成交信号
4. 为了响应速度跳过风险
5. 把未知信息补成事实
6. 与 ALI_RFQ_SCAN() 和 ALI_RFQ_BID() 混用

## 13. 信息不足时的处理

未达到最低运行条件时，不得强行生成正式结果。必须列出缺失、冲突和待验证参数，并说明能否先做初步分析。

## 15. 验收标准

2. 达到最低运行条件后才正式分析
3. 核心判断和风险检查完整
4. 输出符合规定结构
5. 不把待验证信息写成事实
